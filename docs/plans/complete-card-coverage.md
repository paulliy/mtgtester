# Complete card coverage plan

Prepared 2026-09-06 from the current working tree and local Oracle cache. Status: active; W1 and W2 are complete.

## Scope and measured baseline

Complete means every unique card in the 12 committed coverage decks plus the frozen 200 EDH staples is faithfully modeled and behaviorally verified. It does not mean all Magic cards or all Commander-legal cards. The population is deduplicated by Oracle ID, including commanders, companions and all relevant faces.

| EDH staples           | 189/200 (94.5%) |        11 |           200/200 |
| Combined unique cards | 757/906 (83.6%) |       149 |           906/906 |

cards. The baseline table above remains the immutable starting point used to calculate package
deltas.

Current measurement (2026-09-19, local Oracle bulk): **506/802 fixture cards (63.1%)**,
**180/200 staples (90.0%)**, and **599/906 deduplicated cards (66.1%)** are modeled.
Token Triumph is **60/73**. The earlier 2026-09-08 checkpoint is historical: catalog review
contained implementations that claimed unsupported semantics, so its modeled totals must not be
used as current coverage. The 906-card target remains open; CI and passing tests certify the
currently supported subset, not completion of that target.

Measured with `bun run coverage --json` and `bun run staples --json`. The appendix preserves all current blocked cards and their diagnostic reasons. Counts supersede the historical baselines in [post-Tier-3 coverage](post-tier3-card-coverage.md) and [EDH staple coverage](edh-staple-coverage.md); those documents remain useful implementation history. Of the 138 fixture cards, 70 have one reported reason, 48 have two, 16 have three, three have four, and one has five. A reason is not necessarily one missing primitive.

Both Brigid and Pramikon fixtures currently contain 102 cards. Keep them in the coverage denominator; do not use `--strict` to improve the percentage. Deck legality remediation is a separate prerequisite for whole-deck gameplay tests.

Split each package into small primitive-plus-card changes, remeasuring after each. Within a package, first complete single-reason cards and cards that finish a deck, then multi-package cards. Do not estimate coverage gain by adding overlapping mechanic-family counts.

The appendix is a planning allocation from diagnostic text, not proof that each primitive is absent. At the start of each package, inspect the existing consumers and reuse working support before adding IR variants. Review the full Oracle text even when only one clause is reported. Unique mechanics are explicit work, not grounds for approximate overrides.

## Implementation locations

- Authoring and grammar: `packages/engine/src/cards/interpret.ts`, `templates.ts`, `tokens.ts`, `selector.ts`, `value.ts`, `condition.ts`, `ability.ts`, `definition.ts`, `rule-statics.ts` and `overrides/`. Follow [ADR 0025](../decisions/0025-card-template-layer.md): grammar first, template-based overrides when composition is card-specific, deliberate handled-line and snapshot updates.
- Execution: engine `actions/`, `mana/`, `effects/`, `stack/`, `turn/`, `combat/`, `sba/`, `state/` and `flow/`, as applicable. Every new IR producer must have an executable consumer and a behavior test. Use `unimplemented()` until all claimed semantics work.
- Decisions: engine legal actions and views, shared protocol types, bot decision handling and web choice rendering. Providers select engine-generated legal options; they do not infer legality. New choices must work for both humans and bots without revealing hidden information.
- Measurement: `packages/server/src/cards/coverage.ts` and the coverage/staple CLIs. Add a frozen-population completion check; current fixture CLI can skip failed imports, so a percentage alone cannot establish completeness.

## Verification and definition of done

For every newly modeled card, record Oracle ID, exact Oracle fixture, owning package, all required primitives, behavior-test paths, parser/snapshot status and coverage delta. Include a real printed-text interpretation assertion plus a gameplay assertion for each distinct rules clause. Shared primitive tests can cover common semantics, but each card must demonstrate correct wiring. Test relevant negative cases rather than only successful resolution.

Run focused regressions, then `bun run test`, `bun run typecheck`, `bun run typecheck:tests`, `bun run lint`, both coverage reports, and the override/interpret snapshot checks (`bun run scripts/snapshot-override-defs.ts --check` and `bun run scripts/snapshot-interpret-defs.ts --check`). Run format checks for changed files and web build/e2e checks when decision surfaces change. Audit snapshot changes; do not refresh them blindly. Keep effect-op, rule-static and ability-cost consumer guards passing.

`bun run test:implemented` is supplemental evidence: the current runner is centered on Token Triumph and includes hard-coded PASS output. It does not certify the entire 906-card population. W0/W11 should make its failures propagate and extend actual behavioral coverage to the other decks, or provide a separate strict runner.

For every deck that reaches full modeled coverage, use legal deck inputs to run fixed-seed heuristic and random games and replay the same action sequence to the same state. Exercise every new decision kind directly; random games alone may never encounter it. Verify failures are surfaced, rather than discarded from batch metrics. Preserve hidden information and deterministic RNG, including random selections and library ordering.

Completion requires all 12 fixtures present, all 200 staple names resolved, the frozen union still 906 unique cards, zero unmodeled reasons for all 906, all required behavior checks passing, and no unresolved game-stopping regressions in the acceptance runs. Report coverage regressions honestly if correctness work exposes previously false modeled claims. Population changes require an explicit baseline revision rather than silently replacing the denominator.
