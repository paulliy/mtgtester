## What it found

- **A mandatory trigger made optional goes unnoticed (109).** Tests drive decisions with
  `pump()`, whose default answers an unexpected yes/no with yes, so a "may" where the card says
  "must" passes. A test kills it by asserting the trigger asks no yes/no question, or by declining
  where the card offers a decline. Where the effect already offers its own decline (Chrome Mox's
  "Exile nothing"), asking first reaches no new state and the mutant is equivalent.
- **Amounts not pinned (45).** Tests that check a creature died, or a card moved, without the
  number: Mizzium Mortars' scenarios passed with 3 damage instead of 4 until their damage events
  asserted the amount.
- **Unreached (59).** The hook applies only where a card's definition enters a game, so a test that
  builds an ability by hand and calls `executeAbility` cannot prove the card. These cards need a
  test that loads the card itself.
- **A mutant that exhausts the heap.** Widening Celebrate the Mountain-king's per-opponent target
  slot to every controller makes target enumeration run a test worker out of memory. The run
  records it as a crash, not a kill; the unbounded enumeration is a liveness case for the phase 4
  fuzz work.
- **Runner scenarios and strict drivers.** A scenario whose script answers a decision the mutant
  removes ends on the runner's own refusal (an unused step), which is a strict-driver failure, not
  an assertion, so it does not kill. Path to Exile's dropped effect survives this way.

Fixed in this pull request: Mizzium Mortars (damage amounts), Ettercap (its reach, through the new
`keywords` scenario expectation) and Chrome Mox (the pilot; its one survivor recorded as
equivalent, after the run had reached it). The mini-pilot cards are unreviewed, so they are not in the tables.
