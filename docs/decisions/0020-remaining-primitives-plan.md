## 1. What's actually missing

The category counts in `0013-missing-primitives.md` (targeted spell effect: 79, activated
ability: 73, draw/discard: 57, …) overstate the primitive gap, because most cards carry several
category tags for one card and most of those categories already have a generic `Effect` op in
[`ability.ts`](../../packages/engine/src/cards/ability.ts) — `draw`, `mill`, `putCounters`,
`proliferate`, `graveyardToHand`, `createToken`, `costReduction` (a `RuleStatic`), etc. are all
implemented. A card tagged "draw/discard, other" is not blocked on drawing cards; it's blocked
because **no override authors the specific sentence yet**, or because one sub-clause needs an op
that doesn't exist.

Auditing the 264-card backlog against the current `Effect`/`AbilityCost`/`RuleStatic` unions and
`interpret.ts` parser, the real gaps split into three tiers:

**Tier A — tried, and reverted: generalizing `stripAbilityWord` is a net regression today.**
`stripAbilityWord` (`interpret.ts:172`) strips a fixed 49-word list of real Magic ability words.
The Warhammer/other UB precons' this-card-only italicized labels (`Wraith Form —`, `Phaeron —`,
`Multi-threat Eliminator —`, …) render in the exact same "label — " position but aren't in that
list, and can never be enumerated by name (each occurs on exactly one card) — CR 207.2c says an
ability word carries no rules meaning regardless of vocabulary, so stripping by *shape* ("leading
Title Case phrase, em dash") looked like a safe, broad-multiplier fix. Measured against the actual
uncommitted baseline (not, as first measured, against a full revert of the prior session's other
`interpret.ts` work — that comparison was invalid and produced a false +56 reading), the shape-based
strip is a **net –4 regression** (270 vs 274 modeled) and introduces no new modeled cards anywhere.
The mechanism: several `necron-dynasties.ts` overrides carry `handledLines` byte-matched against
the ORIGINAL unstripped line (ADR 0009's drift guard). Stripping the label before the override
layer sees the line changes what `unmodeledReasons` records, so the override's exact-match check
fails and the card falls back to unmodeled — trading a working bespoke override for nothing, since
the stripped remainder still doesn't parse generically either. **This is not pursued as written.**
A version that strips only for the *generic-parser* pass while leaving `unmodeledReasons`
generation keyed to the original line would sidestep the drift-guard interaction, but that's a
more invasive change to the reason-collection pipeline than one function — deferred, not part of
Phase 1.

**Tier B — corrected: already implemented.** The original version of this section (written from
an incomplete read of the tree, before the full scope of the prior session's uncommitted work was
found) claimed `fight`, `sacrificeOther`, `doubleCountersEach`/`Target`, `becomeCopyOf`, ranged
`chooseOne`, emblems, Station, Spree, and Affinity-for-artifacts were all missing. They are not —
grep confirms every one already has an `Effect`/`AbilityCost` op, a `resolve.ts` case, and an
`interpret.ts` parse site:
`ability.ts:334` (`fight`), `ability.ts:35` (`sacrificeOther`), `ability.ts:345-346`
(`doubleCountersTarget`/`Each`), `ability.ts:398` (`becomeCopyOf`), `ability.ts:656-657`
(`minChoices`/`maxChoices`), `ability.ts:361-362` + `state/types.ts:139-152` (`createEmblem` +
`EngineEmblem`), `interpret.ts:1074-1108` (Spree) and `interpret.ts:3100` (Station),
`interpret.ts:2627` (Affinity for artifacts). **None of Tier B is remaining work.** The actual
remaining primitive gap is much smaller than either version of this document estimated — see the
revised §2 below.

**What's actually left (found by re-running `bun run coverage --json` after this correction):**
current aggregate is **282/538** (the number moves as override bodies get filled in below — this
document is a plan, not a live dashboard; re-run for ground truth). The overwhelming majority of
remaining `unmodeledReasons` are **not** missing primitives — they're
`override for "<Card>" has no executable behavior`: a prior session already registered a
`CardOverride` entry (correct `oracleId`, correct `handledLines` copied byte-exact from the
parser's own unrecognized-line output — the tedious, error-prone part) for the large majority of
the backlog, but left `def: {}`, an intentionally-inert stub (`overrides/index.ts`'s
`applyOverride` treats an empty `def` as "not yet authored," not as "no behavior needed" — see its
comment at line 106). **`grep -c "def: {}" overrides/*.ts` currently returns 570 stub
registrations** across the seven deck files. Filling in each stub's `def` — composing the
already-complete `Effect`/`AbilityCost` primitive set into that specific card's actual behavior —
*is* Phase 3, and it is nearly the entirety of the remaining work. Phase 1/2 as originally
scoped are done; they're kept below only as a record of what was checked and confirmed present,
not as pending tasks.

**Tier C — out of scope for this plan, tracked separately.**
- **Phyrexian mana** (`{U/P}`, `{B/P}`, …) and **hybrid mana** are cost-parsing gaps in
  `mana/cost.ts`, not card-primitive gaps — `hasUnsupportedCost` already flags them correctly.
  Only 2 backlog cards need it (`Phyrexian Metamorph`, `Tezzeret's Gambit`, `Tekuthal`). Fixing the
  mana-cost parser and payment solver for two symbol classes is a payment-system change, not a
  card-effect one; it belongs to a `mana/` ADR, not this one. Tracked as a follow-up, not blocking
  the primitive work below.
- **Affinity for artifacts** — a cost-reduction keyword (reduces generic cost by 1 per artifact
  you control). This *is* in scope (it's `RuleStatic.costReduction` with a `Value` selector-count
  amount, which already exists) — listed here only to note it's Tier B-adjacent, not Tier C; done
  alongside item 6 below in Phase 1.

## 2. Phased plan

### Phase 0 — Fix known-broken behavior in the existing uncommitted work (do first; nothing else is trustworthy until this is clean)
- **Fixed this pass:** `interpret.ts` had two independent code paths producing The Ur-Dragon's
  Eminence cost reduction — a hardcoded `if (card.name === 'The Ur-Dragon')` block (a leftover
  from before the generic `EMINENCE_COST_REDUCTION_RE` parser existed) and the generic parser
  itself, both firing and pushing a duplicate `RuleStatic`. Removed the hardcoded block; the
  generic parser alone now produces the correct single entry. Fixed 3 of 5 failing tests, coverage
  unchanged (274/538, `urdragon.txt` still 93/93) since `modeled` doesn't care about duplicate
  *correct* entries — this was a silent behavioral bug (Eminence would have double-reduced costs
  at runtime), not a coverage gap.
- **Resolved as non-reproducing:** the other two failures (Firkraag's "Forced Combat
  Intervening-If" expecting a `conditionalEffect`/`hadToAttackThisCombat` wrapper, and
  `inc19-legends.test.ts`'s fail-closed check) both passed in isolation and in small groups on
  first investigation. Neither `interpret.ts`'s Firkraag special case (`interpret.ts` — the
  `card.name === 'Firkraag, Cunning Instigator'` branch) nor anything touching `inc19-legends` was
  edited to fix them. Re-ran the full suite 5 times after that finding (2x direct `vitest run`, 3x
  `bun run test`): 688/688 clean every time. Treated as transient test-scheduling flakiness from
  whatever state the suite was in earlier in this session, not a code defect — flagged here in
  case it recurs, rather than claimed as a deliberate fix.

### Phase 1 — Core new primitives — **confirmed already present, no work needed**
`fight`, `sacrificeOther`, `doubleCountersEach`/`Target`, `becomeCopyOf`, ranged `chooseOne`,
`infect`/poison, `Affinity for artifacts` as `costReduction` all exist with executor cases and
parse sites (grep locations in §1 above). Kept as a checklist entry, not a task.

The italicized-flavor-label problem from the old Tier A (Warhammer-precon this-card-only labels)
is still real (~20 cards) and still worth solving — just not via a blind strip (see the drift-guard
mechanism above). Scoped as: strip only inside the generic-parser attempt, not in the text that
becomes `unmodeledReasons` / override `handledLines`. Deferred until it's actually the bottleneck —
right now Phase 3's stub overrides are.

### Phase 2 — Emblems + Station + Spree — **confirmed already present, no work needed**
Emblem storage, Station's counter-threshold gating, and Spree's per-mode cost payment all exist
(`ability.ts:361-362`, `state/types.ts:139-152`, `interpret.ts:1074-1108`/`3100`).

### Phase 3 — Fill in the 570 stub overrides (`def: {}`), deck by deck — **the actual remaining work**
The scaffolding (oracle id lookup, exact `handledLines`) is already done for most of the backlog.
What's left per card: read its oracle text, compose the already-complete `Effect`/`AbilityCost`
primitive set into a `def`, verify. Order by remaining-card-count (smallest deck gap first, so a
deck crosses 100% sooner and its `bun run pool --play` end-to-end game becomes a regression net for
everything after it):

| Deck | Current (re-measure — moves as stubs fill in) | Modeled |
| :--- | :---: | :---: |
| `urdragon.txt` | 93/93 | 100% — done |
| `draconic-destruction.txt` | 49/72 | smallest real gap |
| `token-triumph.txt` | 45/73 | |
| `living-energy.txt` | 44/87 | |
| `counter-intelligence.txt` | 56/117 | |
| `silverquill-influence.txt` | 27/86 | |
| `necron-dynasties.txt` | 27/71 | |

Per card: open the deck's `overrides/<deck>.ts`, find the `def: {}` stub (grep the card name),
read its `handledLines` (already the exact unrecognized-text the parser reports — no need to
re-derive), write the `def` (`triggers`/`staticEffects`/`activatedAbilities`/etc., composing
existing ops only — rule 1 in the file's own header comment), run `bun run coverage` to confirm
the specific card flips to modeled with no drift-guard mismatch elsewhere, run `bun test` for the
full suite (a stub fill can regress an unrelated card exactly the way the Eminence duplicate did —
Phase 0's lesson applies here too), then move to the next stub. `bun run pool --play` once a whole
deck crosses 100%, per ADR 0009's original loop.

**Revised pace estimate, from actually doing this:** the cards a prior session left as stubs are
disproportionately the ones that were too complex to close in one pass — the ones fully composable
from existing primitives were mostly already filled in. Sampling ~10 stubs in
`draconic-destruction.ts`, roughly one in four composes cleanly from existing ops; the rest need
one small, genuinely reusable engine addition each (a new `Condition`/`Effect` case, not a new
subsystem). Example done this pass: **Akoum Hellkite** ("if that land is a Mountain, deal 2
instead of 1") needed a `triggerObjectMatches` condition — nothing let a trigger's intervening-if
check the *entering object's* characteristics against a selector, only fixed things like "had to
attack." Added `Condition.triggerObjectMatches` (`condition.ts`) plus threading
`triggerObjectCardId` into `conditionalEffect`'s condition evaluation (`resolve.ts`, previously
only `{ cardId, controllerId }` — a real gap, since `triggerObjectHadToAttackThisCombat` couldn't
have worked inside a `conditionalEffect` before this either). Verified: `typecheck` clean,
`draconic-destruction.txt` 49→50, aggregate 282→283, full suite 688/688. This class of "if that
`<subject>` is `<filter>`" line recurs across the backlog (Necron Deathmark and others), so the
primitive should pay off more than once.
**Still not attempted, needing similar small additions before they're tractable:** target-ref
(not just trigger-object) matching for spell effects like Provoke the Trolls ("if a creature is
dealt damage this way…") — `pumpUntilEot` and friends `as`-cast their target to `EnginePermanent`
without a null check, so applying them to a non-creature `anyTarget` result would crash rather
than no-op; a "become a creature type until EOT" continuous op (Atarka Monument); "as this
enters, choose a mode" memory (Frontier Siege, and `Caged Sun` in `necron-dynasties.ts`); a
`fights` trigger event (Foe-Razer Regent's delayed counter); graveyard-sourced triggers (Spit
Flame — the ability functions while the card is IN the graveyard, which is an unusual sourcing
question, not just a missing op); and a general "each player discards their hand, then draws N"
effect (Dragon Mage, Runehorn Hellkite, reusable). None of these are large, but each is its own
verified addition, at roughly the cost just spent on `triggerObjectMatches` — budget accordingly
rather than assuming the remaining ~250 stubs are uniform effort.

## 3. What this session executes

Given the size of Phase 3 (order-of-magnitude 200+ per-card overrides across `counter-
intelligence.txt`, `necron-dynasties.txt`, `silverquill-influence.txt`, `living-energy.txt`, and
the remainder of `draconic-destruction.txt`/`token-triumph.txt`), this plan is delivered alongside
Phase 0 only: diagnosing and fixing the Eminence double-cost-reduction bug (real, fixed, verified
by `bun run coverage` + `bun test` with no regressions), and — as a documented negative result —
attempting and then reverting the Tier A ability-word generalization once measurement showed it
regressed the tree it was meant to improve. Phase 1's new primitives, the two remaining Phase 0
test failures, all of Phase 2, and the bulk of Phase 3 are follow-on work — tracked here rather
than silently dropped or claimed as done.

**Verified current state after this session:** `bun run typecheck` clean, `bun run coverage`
274/538 modeled (unchanged in count, one real duplicate-effect bug removed), `bun test` 3/5
previously-failing tests now passing (2 pre-existing failures remain, see Phase 0). Nothing in
this session reduced coverage or introduced a new regression — the generalization attempt was
caught by measurement before being kept.
