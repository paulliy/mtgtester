# Architecture decision records

Each file here records one decision: what was chosen, why, and what it costs. The table below lists every ADR with its status, the date it was written, and any later ADR that replaced or changed part of it. [The original brief](../mtg-commander-ai-simulator-brief.md) is the v1 spec; where it disagrees with an ADR, the ADR wins.

- [0033 Forge-informed card authoring](0033-forge-informed-card-authoring.md): the current card authoring workflow.

- [0044 Tactician escalation triggers](0044-tactician-escalation-triggers.md): when the bot asks the model.

## Statuses

- **Accepted**: the decision holds. A "Status note" line in the ADR gives any limit, such as "accepted in part".
- **Proposed**: written down but not yet agreed.
- **Completed**: a plan or backlog whose goal has been met. It is kept as a record.
- **Superseded by NNNN**: replaced as a whole. A partial replacement or amendment shows in the last column instead, and the older ADR still holds where it is not changed.

To add an ADR, take the next unused number, put a `Status:` line in the form above near the top, and run `bun run adr:index`. CI runs `bun run adr:index --check`, which fails on a stale table, a duplicate number, or a missing status line. Two ADRs once shared 0013 and two shared 0037; the later ones were renumbered 0049 and 0048, with a note at the top of each.
