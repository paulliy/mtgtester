# Current state

This Bun/TypeScript monorepo contains a working local Commander simulator:

- `packages/engine`: authoritative deterministic rules engine.
- `packages/bot`: seeded heuristic decision provider and bounded combat search.
- `packages/server`: human/bot/LLM orchestration, deck import, SQLite, batches, AI benchmarks, and HTTP/WebSocket APIs. `serve:table` is the separate table server ([ADR 0031](../decisions/0031-multiplayer-tables.md)): one worker per game, clocks and fallback bots, and the exposure rules in [table hosting](table-hosting.md).
- `apps/web`: Vue 3 spectator and single-player UI, including the Card Test Lab. `--mode table` builds the table app (lobby, table board, post-game replay) into `apps/web/dist-table`, a bundle with no tester views.
- `packages/shared`: cross-package game, protocol, view, database, and batch types.

Spectator play, one-human-versus-three-opponent play, replay, supported-pool decks, imports, batches, and statistics are implemented. Tables for two to four people with bots in the empty seats are implemented end to end (multiplayer plan M1–M6); `bun run test:e2e:table` plays one in two browser contexts against the built bundle, and `bun run dev --table` runs the table app with a dev server. The optional LLM provider is OpenAI-compatible (configured through `.env.example`); random and heuristic bot providers do not need an API key.

## Known residual risks

- Full list: [audit remediation](../reviews/audit-remediation-2026-09-05.md).
- Engine speed on big boards: the 71-permanent fuzz board (Council of Reeds copying itself, `fuzz-2`) now plays in 27 seconds instead of 100, and its slowest step takes 1.5 seconds instead of 11.7 ([big-board review](../reviews/big-board-and-tables-2026-11-04.md)). The layer-cache digest is now computed once per read scope (building a priority menu, gathering mana sources, matching triggers) and once per SBA check rather than once per query, so those loops are no longer quadratic. What is left is the stateful mana planner: a board with a state-dependent source (Exotic Orchard) sends every castability check through a search that copies the game and reruns the layer pass for each activation it tries.
- Wide token turns (fuzz-203: Rabble Rousing with Champion of Lambholt, 567 resolutions and 2,272 objects in one turn, about 300 permanents): the game now plays in about 56 seconds instead of 282, and in about 140 under fuzz's strict invariants instead of more than 600, with every decision unchanged. The SBA Aura check (`enchantAllows`) now reads in one read scope instead of re-digesting the board for every candidate; `computeCharacteristics` looks battlefield membership up in a set per read scope; the CR 613.8 dependency probe builds each permanent's selector candidate once per unchanged working set; and under `strictInvariants` each cached layer pass is verified at most once, or once per tapped state of the board for a pass that read no tapped status (it was re-verified about every 64 hits, and that board hit each pass about 1,200 times). What is left is still quadratic in board size: about 6,700 layer passes that turn, each over the whole board, and every resolution's priority round, views and trigger matching walking all 300 permanents. The next step is incremental layer results (recompute only what a change can reach) rather than more caching.
- The stateful mana planner no longer exhausts its budget over a color only a dynamic source could make, or over a life cost the payer cannot meet. It is still exponential in the number of distinct sources when no bound can disprove a payment, and halts the game past 2,048 states.
- The stateful mana planner no longer halts a game over a "sacrifice a creature: add mana" source (Ashnod's Altar, Phyrexian Altar, Illuminor Szeras) next to a state-dependent source. It used to skip the sacrifice source, find no payment, and stop with an unmodeled-mana-payment error, whether or not a sacrifice could have paid. A cast no sacrifice can pay is now unpayable, and one only a sacrifice can pay is offered, with the player choosing the victim when they pay. In a 40-game bot league, 6 games halted this way before and none after; the 34 that finished before played out turn for turn the same. It holds only while nothing in play could give production back when a permanent leaves (a "loses all abilities" or type-setting static, a ban on activating abilities, a replacement effect, a power-gated source next to a computed pump). A board with one of those, or a sacrifice source next to a source that costs mana to activate, still halts.
- The weekly bulk-data job has its baseline (`bulk-population.json`, for `oracle-cards-20261103220204.jsonl.gz`) and passed locally against that file. The repository variables `SCRYFALL_BULK_URL` and `SCRYFALL_BULK_SHA256` (values in `data/README.md`) still have to be set before it can run in CI. That bank also differs from the pinned coverage fixture on 133 of its 1,031 cards; refreshing the fixture is a separate change (`coverage:rebaseline`).
- Tables: a LAN game with `--insecure-lan` has been played between two network namespaces on one machine, and the served bundle has been reviewed ([big-board review](../reviews/big-board-and-tables-2026-11-04.md)). A game between two physical machines, with real browsers on a real network, is still worth one manual run. Players' browsers fetch card images and token art from Scryfall directly.
- Browser-trial payment regression: covered by focused normal-path tests. The one-off reproduction script `scripts/reproduce-browser-payment.ts`, which reused the original derived seed, was retired; it is in history at `fae4d11`. The original generated deck configuration was not captured, so it was never an exact full-game replay. See [browser trial](../reviews/browser-experience-2026-09-05.md).
